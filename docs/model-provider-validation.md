# 历史模型渠道验收记录

> 本文是旧 BeefTV/BeefAPI 托管渠道的归档记录，不是当前模型渠道的操作手册。旧渠道登录、托管媒体上传、云端超分和付费验收流程已经退出产品运行面；不要依据本文连接旧服务、提交新任务或进行付费复验。

## 归档范围

历史验收使用 `fixtures/model-catalog/beefapi-20261013.json` 中的 47 个模型名称和接口类型。该 fixture 不包含账号、凭据、请求正文或媒体链接，模型目录也不应被当作当前可用目录。

当时的结果是 44 个模型取得可用结果，3 个模型未通过服务可用性验收：

| 模型 | 历史观察 | 历史归因 |
| --- | --- | --- |
| `gemini-3.1-pro` | 上游 HTTP 503 | 当时的上游服务不可用 |
| `gemini-3.7-flash` | 上游 HTTP 503 | 当时的分组没有可用渠道 |
| `grok-imagine-video-1.5` | 创建被接受，原任务随后失败 | 当时的上游账号额度耗尽 |

这些结果只描述对应版本、目录和服务状态，不能证明今天的模型、渠道、额度或协议仍然可用。失败任务当时要求查询原任务，不以重新生成替代；该规则仅作为历史验收背景保留。

## 历史适配修复摘要

旧适配器曾处理以下问题：

- 图片模型目录误归类为聊天模型，或参考图请求使用了错误的通用协议；
- 视频模型的 JSON 创建、查询、下载和失败状态解包不一致；
- 音频 multipart 文件名、Responses 文本块解包和发送前失败归类不准确；
- 已提交但结果未知的任务被错误地自动重发。

上述修复属于旧托管渠道的历史实现背景。当前实现通过 Provider/Protocol 和各自的模型合同处理请求，不应恢复旧 BeefAPI 登录或专用渠道入口。

## 当前模型渠道路径

- New API 通过设置中的连接入口同步账号下 `videoCanvas` Key 和完整模型目录，见[New API 模型渠道连接](content/docs/backend/desktop-account.mdx)。
- 自定义 Provider/Protocol 由用户在本地模型配置中维护，能力和媒体合同以当前配置为准。
- 历史任务只可按保存的任务身份和当前恢复合同查询、取回结果；不能用旧托管服务重新创建任务。
- 当前目录、模型可用性和协议验证应以代码、当前 Provider 配置及对应的本地 API 记录为准，不使用本文的 fixture 或历史服务地址。

## 归档证据与限制

历史记录包含图片、视频、音频和语音识别的适配器检查，以及旧配置刷新、恢复和错误归类检查。记录中的媒体结果、账务结果和服务状态均绑定当时的代码与测试环境；不代表当前运行时已连接这些服务。

本文不再提供账号、密钥、服务地址、测试命令、预算或付费验收步骤。需要验证当前渠道时，应使用对应 Provider 的本地配置和项目现行验证合同，并遵守“不尝试视频生成”的任务范围。
