# 视频模型与参考素材合同

视频任务统一经过素材归属检查、能力检查、素材读取、协议适配、任务轮询和结果保存。模型名称相似不代表请求格式或素材能力相同。

生成完成后的下载显示「正在取回生成结果」。单次状态读取最多等待 45 秒，单次内容下载最多等待 5 分钟，仍受调用方更短的截止时间限制；网络暂时中断时按原任务 ID 继续查询和下载，不重新提交付费生成。创建请求保留原生成等待时间。

历史任务保留其提交时的查询身份和交付合同；当前 New API 与自定义渠道使用各自选择的协议与查询频率。恢复只查询原任务并下载结果，不重新生成。

画布按原输入重试视频前会重新读取任务的 `outcome`。若最新状态仍在取回结果，先更新本机节点状态并停止重试，避免过期的画布状态触发新的生成请求。

视频任务的执行期限由后端运行策略控制（默认 60 分钟）。前端默认持续观察后端终态，不在 32 分钟自行判断执行失败；调用方显式设置的观察时限、停止观察和连续状态查询失败仍会结束本次观察，且不会取消或重新提交上游任务。

视频自动轮询、手动取回与下载链接刷新均校验协议解析出的任务 ID；响应省略 ID 时沿用原 ID，返回不同 ID 时停止取回。Seedance 专属协议与 OpenAI 兼容视频协议读取 `metadata.generation_status` / `generationStatus` 与 `metadata.url`，同时支持 `data` 包装。生成百分比只作为进度信息，100% 不代表文件已经取回；只有成功状态及有效文件完成下载后才交付结果。

墨羽 Seedance 的参考图片、视频和音频统一通过 `/img_up` multipart `file` 上传，并用同一 `img_id` 查询 `/q`；每个素材独立上传，所有素材就绪后才创建生成任务。服务返回的 `img_url` 有效期为 25 分钟，后端按上传开始时间记录保守过期点，并在每次新建任务前核对每个 URL 的来源、有效期和最终请求体中的顺序/内容与上传回执一致。校验失败时停止请求，不会把过期或错配链接交给视频上游。重试会重新上传引用素材；恢复既有上游任务则只查询，不重新创建或上传。

进度从 `progress`、`progress_percent`、`progressPercentage`、`percent` 等字段及 `data/task/result/metadata` 等包装读取。带百分号的字符串和名称明确包含百分比单位的字段按 0–100 解析；无单位的 `progress/completion` 在 0 与 1 之间时按比例换算，整数 1 保持为 1%。非法值忽略，已有进度不因较旧响应倒退。结果下载使用独立的字节进度，刷新下载地址的查询保留「正在取回生成结果」阶段。

直链下载发生可恢复的网络错误、外部签名地址过期，或连续 10 秒没有收到新字节时，客户端按所选 Provider 的原任务查询协议刷新地址；不调用已退役的托管备用接口，也不重发生成。持续收到数据的下载不会被 10 秒计时截断，仍受原有单次下载期限、文件大小和并发限制。

Seedance 专用调度与声明式视频插件共用该下载合同，包括直接结果 URL 和独立内容端点。API 凭据、渠道自定义请求头不发送给外部视频地址；重定向仍经过统一出站地址校验。网关本身拒绝凭据或用户取消时停止取回，不触发备用下载或重新生成。取回文件不读写模型生成的熔断状态，避免素材线路故障阻止已完成视频的下载。其他供应商沿用原行为。

出站连接仅尝试已通过地址校验的 DNS 结果，先尝试首选地址，250 毫秒后尝试另一地址族，再尝试其余地址。这样可以绕过不可用的 IPv6 或 IPv4 路线；不会重新解析主机名，也不会因此重发生成请求。默认允许本机回环、RFC1918 和 Tailscale/CGNAT（`100.64.0.0/10`）上的 HTTP/HTTPS 模型服务；链路本地（含 `169.254.169.254`）、未指定地址、组播，以及 URL 中的账号密码仍然拒绝。`CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 不能放行这些地址。需要公网隔离时设置 `CANVAS_ALLOW_PRIVATE_UPSTREAMS=false`，再按主机名精确放行。

## 外接视频协议选择

第三方服务的新视频模型需要明确选择请求协议；仅有“OpenAI 兼容”或模型名称不能确认视频接口格式。目录明确标注合同且对应插件已启用时，才可采用该协议。已有用户配置保持原样。

刷新已识别视频模型的目录或重新加载 New API 配置时，保留已选择的视频协议及自定义插件；模型名称匹配不覆盖该选择。`seedance-2.0-gz` 等模型即使支持多图，若当前选择的是单图 Sora 协议，仍会在本地提交前触发协议限制，需核对渠道实际请求格式后选择对应协议。

选择 `sistinelove-seedance-video` 协议并使用 `video.sistinelove.cn` Seedance 模型时，后端会将每项图片、视频和音频参考素材（包括本地资源、Data URL 和已有 HTTPS 链接）分别上传到 `https://img.sistinelove.cn/img_up`。上传为并发数最多 3 的 multipart `file` 请求，Header 携带独立 64 字符 `img_id`；随后以同一 Header 调用 `GET /q` 获取匹配的 `img_url`，全部链接就绪后才发送生成 JSON。远程源仅接受公网 HTTPS，下载有大小限制并写入临时文件，上传或查询失败会阻止生成请求。该路径不按模型名称影响其他服务商或协议。

自定义渠道统一使用用户明确选择的请求协议，不按域名或模型名称自动更换协议。选择「视频生成 JSON · ratio / duration」后，同一格式的其他服务地址和模型也可完整发送多张参考图；顺序保持不变，未指定首尾帧的图片明确标为 `reference_image`。模型能力设置中的数量等限制仍生效。旧配置若误选了 `newapi`（Sora multipart），请在模型的高级设置中选择与服务商实际接口一致的 JSON 协议。插件未安装或停用时仍在发送前失败。

- OpenAI Videos / Sora 使用 `POST /v1/videos` 和 multipart，最多一张参考图。不支持的多图、参考视频、参考音频、尾帧及蒙版会在提交前报错。
- OpenAI 已于 2026-09-24 关闭官方 Sora 2 模型与 Videos API，且没有一对一的替代接口；这条协议现在只对仍转发同名 `/v1/videos` 合同的第三方中转有意义。用普通 OpenAI Key 直接在 `api.openai.com` 生成视频不保证可用。
- Google 已停止 Gemini API 的 Veo 预览模型（2026-10-22）与 Veo 3.0 / 2.0 正式模型（2026-06-30），官方建议改用 Gemini Omni Flash；`gemini-veo` 协议保留给仍转发同名 `predictLongRunning` 的中转或尚未关闭的模型。
- Runway 的 `promptImage` 按模型区分：`gen4.5`、`gen4_turbo`、`gemini_omni_flash`、`grok_imagine_1_5` 等模型的 `position` 只有 `first`，带尾帧会在提交前报错；`veo3.1`、`kling2.5_turbo_pro`、`seedance2_5`、`h3_max` 等支持尾帧的模型照常发送，本地只拦官方明确限制的单帧模型。创建与查询都带官方的 `X-Runway-Version`。
- Luma 的 `keyframes.frame0.url` 只接受在线图片地址：本地首帧先上传到对象存储换成在线地址，拿不到在线地址时在提交前报错（`reference_media_requires_url`），不会把 data URL 发进该字段。
- 「视频生成 JSON · ratio / duration」使用 `POST /v1/video/generations` 和 JSON，发送 `images` 对象数组及图片角色、整数 `duration`、`ratio`，并从查询结果 `data[].url` 取回视频。只有服务商文档符合该格式时才选择。
- 既有 NewAPI Video Generations 使用 `seconds/aspect_ratio/image_urls`，与上一项的字段不同；方舟原生、fal 和其他专用协议也须按各自文档选择。

在「设置 → 模型服务 → 管理服务 → 高级模型设置与测试 → 配置使用」选择协议，并按服务商文档设置素材与参数限制。生成测试会收费；保存配置和选择协议本身不会提交生成。HTTP 错误或超时后不会自动改用其他协议重发。

Seedance 重新生成会重新读取原参考资源、上传并取得新的 `img_id` 与链接，临时链接不覆盖任务中保存的原素材引用。断线后的原任务查询只沿用上游任务 ID，不重新上传或提交生成。上游明确失败时停止自动取回；审核失败需要修改提示词或参考素材后创建新任务。

## 企业模型

`backend/internal/providerpreset/video_contracts.json` 是已核验企业视频线路的共用声明，后端模型目录、素材处理和前端配置直接读取同一份文件。声明包含匹配模型、协议、是否允许内嵌素材、是否必须使用 HTTP 参考地址，以及有明确限制时的参考素材数量和生成模式。

`maxReferences` 可只约束部分素材类型；未声明的类型保留原有模型能力限制，`0` 明确表示不支持该类型。前后端都遵循这一规则。

历史配置中的能力快照可继续投影声音开关、时长、分辨率与参考数量。`generateAudio.supported` 表示可选择生成声音，`default` 保留已保存的默认值；支持声音不会自动把用户关闭的声音打开。带 `videoCapabilitiesVersion` 的渠道目录保留其明确能力配置；当前 New API 与用户自定义上游地址使用自己同步或声明的能力。

- Seedance 2.0 / 2.5 使用既有 Seedance 请求处理和素材规格检查。当前 New API、自定义渠道和其他 Provider 依据实际选择的协议与媒体合同传输参考素材；不自动裁剪、压缩或截断。历史任务若仍有原始媒体上传回执，只能按原任务身份恢复，不为新请求重新走退役的托管上传路径。
- Wan 3.0 当前接入支持文生视频和单图生视频，VOD 路由只接受 HTTP 参考地址（`requiresHTTPReferences`）。上传失败会在生成提交前停止，不回退为内嵌数据或 `asset://`；当前接入只开放一张图片，参考视频、参考音频和多图会在提交前拒绝。
- 未声明的模型保留模型目录或用户明确选择的协议，不根据供应商品牌放开本地素材支持。
- 通用素材处理遵循已安装插件的 `requiresPublicMediaUrls` 声明。要求公网地址的线路不会把本机地址发送给上游，也不会自动公开用户文件。
- 只接受公网链接的渠道会在任务入队前检查参考素材，并指出需要替换的图片、视频或音频序号。可换用 HTTPS 素材链接，或在渠道设置中选择与服务商实际接口相符、支持本地素材的协议；不会仅凭模型名称自动切换协议。

## 自定义全参视频服务

服务商支持分片素材上传及全参视频接口时，在模型的高级设置中选择「全参视频」协议。模型名称本身不能证明协议兼容；请按服务商的接口说明选择。

图片、视频和音频参考先上传到所配置的 API 服务，完成后核对字节数与 SHA256，再提交视频任务。素材地址默认必须与 API 同主机。如果服务商另有素材域名，在连接的「高级设置」中填写「素材服务地址」，只填源站，不带路径、账号或查询参数。公网源站使用 HTTPS，端口为空或 443。已填写的本机、局域网或 CGNAT 源站可以是 HTTP，也可以带其他端口；回执里的地址必须与这个源站的协议、主机和端口一致，不能改指另一台局域网机器。未填写时不接受跨主机地址。此设置不会向素材源站发送 API Key。`CANVAS_ALLOW_PRIVATE_UPSTREAMS=false` 时，跨主机素材源站只接受公网 HTTPS 443。

任务结果若返回以 `/` 开头的相对地址，客户端按所配置的 API 源站解析。下载仍受外部地址校验约束；只有同源下载使用该服务的凭据。

## 新增模型验收

1. 核验当前线路的创建、查询和结果格式，以及每种参考素材的传输方式、数量、大小、时长和格式限制。
2. 复用已有协议插件；确有不同线协议时再增加插件。企业线路的例外能力写入共用合同，不在页面中增加模型名称判断。
3. 添加合同与请求测试，覆盖本地素材、数量边界、未知模型不继承能力、配置重载，以及插件缺失或停用。
4. 实际提交最小样例，验证任务终态、结果可读取和保存；接单成功不能替代生成成功。

新增模型仍需要协议核验与实际验收；共用流程减少重复实现，不代替供应商能力确认。
