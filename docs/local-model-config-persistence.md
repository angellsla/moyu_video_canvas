# 本地模型配置持久化

本地桌面模式的模型渠道不再只依赖浏览器 `localStorage`。前端启动时通过 `/api/workspace/model-config` 读取本机快照，渠道发生变化后自动保存；后端将快照原子写入 VideoCanvas 应用数据目录的 `local-model-config.json`。

- 配置文件位于应用数据目录，不进入 Git，也不随前端静态资源更新覆盖。
- 写入采用临时文件 + `rename`，文件权限为 `0600`，目录权限为 `0700`。
- 同一工作区路径上的多个配置句柄共用一把进程内锁；revision CAS 与脱敏密钥保留跨句柄串行。损坏、`null` 或非对象的现有主文件不会被新写入替换。
- 带 `id` 的渠道只按相同字符串 ID 保留密钥；对不上的脱敏占位会拒绝写入，不会把 A 的密钥写进 B，也不会把占位符存成密钥。
- 工作区路径只把「尚未创建的后缀」当成可恢复；符号链接环或权限/非目录错误会失败，不会为同一目录生成两把锁。
- New API 管理账号的用户名和密码仅用于本机连接同步请求，dashboard access token 仅在内存中使用；New API 返回的模型 API Key 随 `newapi` 渠道保存在本地模型配置中，并沿用配置脱敏和文件权限规则。
- 其他手动渠道的 API Key 仍保存在本机配置文件中，不应提交到仓库或日志。
- New API 可用模型以 `https://video.sistinelove.cn/v1/models` 返回的目录为准，不在仓库中写死。重新登录同步时刷新模型列表，并保留仍在目录中的模型能力配置。

首次使用新桌面构建时，如果旧版本仍有浏览器渠道配置，前端会自动迁移到本地快照；后续重装前端资源不会清除模型配置。

旧快照中的 `beefapi` Provider 入口已退场；新配置由 `newapi` 渠道和用户手动添加的服务组成。历史任务内保存的 BeefAPI 任务与凭据引用仍可按既有恢复合同处理，不代表该渠道仍能用于新任务。

画布助手也从这份快照读取模型和渠道凭据。手动渠道只有 `models` 列表、没有对应 `modelProfiles` 时，助手可跟随已选定的默认文本模型，使用渠道指定的对话协议；OpenAI 格式默认使用 Chat Completions。已声明的能力和协议优先，禁用渠道、非文本模型、不支持的协议或缺少密钥仍不可用。New API 的模型目录同样从当前渠道配置读取。
